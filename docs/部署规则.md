# 部署规则 · 冲充电

> 固定上线规范。改动完成后，一律按下述「标准部署流程」执行，无需再重新配置远程仓库或 Pages。

## 二、目录/文件约定

- 应用源码位于 `app/`：`charging-tracker.html`、`charging-tracker.js`、`sw.js`、`manifest.json`、`icon-*.png`、`assets/`。
- `index.html` 必须保持为「重定向到 `charging-tracker.html` 的薄页面」，**不得**替换成整站拷贝——否则会因拷贝陈旧导致首页停留在旧版本。
- PWA 图标引用控制在安全边界内（maskable，内容居中央 60%）。

## 三、标准部署流程（每次发版都走）

1. 完成代码改动后，务必**同步 bump Service Worker 缓存版本**
   - 在 `app/sw.js` 中把 `CACHE_NAME` 从 `ev-charging-vNN` 提升为 `v(NN+1)`。
   - 否则浏览器与线上会命中旧缓存，页面停留在旧效果（常见"改了没生效"的根因）。
2. 本地 git 提交本次改动：
   ```bash
   cd /workspace/app
   git add -A
   git commit -m "<本次改动说明>"
   ```
3. 推送到远端（Pages 会自动从 `main` 重建）：
   ```bash
   git push origin main
   ```
4. 验证线上是否生效：
   ```bash
   for u in charging-tracker.html sw.js manifest.json; do
     curl -s -o /dev/null -w "$u:%{http_code}\n" https://pers1e20.github.io/chongchongdian/$u
   done
   # index
   curl -s -o /dev/null -w "index:%{http_code}\n" https://pers1e20.github.io/chongchongdian/
   ```
   全部返回 `200` 即发布成功。

## 四、写权限/令牌规范（安全约定）

- 远程地址：`https://github.com/pers1e20/chongchongdian.git`（HTTPS）。
- 仓库公开，读无需认证；`push` 需要**写权限令牌**（Fine-grained token，`Contents: Read and write`；如需用 API 查/改 Pages，加 `Pages: Read and write`）。
- 令牌**不写入** `.git/config`、不提交进仓库、不留在工作目录。
- 本次部署采用「临时 AskPass 脚本」方式：写令牌到 `/data/user/work/` 下的临时文件 → 以 `GIT_ASKPASS` / curl header 文件使用 → 用后立即删除。
- 若令牌在环境中重新失效（沙箱凭据不回持久化，需每次现取），回到上述临时脚本方式，让用户提供有效令牌即可。

## 五、已知注意事项

- 改动仅限 `app/` 内文件；资源文件（图标/assets）变更后同样需要 bump SW 缓存版本。
- `index.html`、`manifest.json`、`sw.js`、图标均为 PWA 安装/离线的关键资源，改动后务必过一遍第 3 步的线上 200 校验。
